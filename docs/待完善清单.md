### 2. API Key 不再硬编码

**当前状态**：`backend/api_config.json` 内含完整的 DeepSeek 和讯飞 VMS API Key/Secret。

**做什么**：
- 将 `api_config.json` 改名为 `api_config.example.json`（值替换为占位符）
- 真实密钥改为从环境变量或 `.env` 文件读取
- 确保 `.env` 已在 `.gitignore` 中

### 3. 统一事件系统

**当前状态**：存在两套互不相通的事件系统：

| 文件 | 类型 | 使用者 |
|------|------|--------|
| `events/dispatcher.py` | 同步 dict 回调 | `main.py` 的 `@on()` 装饰器 |
| `services/event_service.py` | asyncio Queue 广播 | 所有 Agent 的 `emit()` |

`main.py` 中注册的事件 handler **永远不会被触发**，因为 Agent 发事件用的是另一套系统。

**做什么**：
- 删除 `events/dispatcher.py`
- 删除 `events/events.py` 中的 `Event` 类（或改为定义事件名常量）
- `main.py` 中的事件监听改为通过 `services/event_service` 订阅
- 或者反过来：删除 `event_service`，将 Agent 的事件发送全部改为 `dispatcher.emit()`

### 4. 修复 main.py 路由重复注册

**文件**：`backend/main.py:82-83`

```python
app.include_router(events.router)   # 第 82 行
app.include_router(events.router)   # 第 83 行 ← 重复
```

删除重复行。

## 🟠 高危（早期会导致核心功能瘫痪）

### 5. 替换 RAG 假向量为真实 Embedding

**文件**：`backend/services/rag_service.py`

**当前状态**：`SimpleEmbeddingFunction` 使用 MD5 哈希 + 位置组合生成向量，不含任何语义信息。向量检索结果随机，完全不可用。

**做什么**：
- 方案A（推荐）：引入 `sentence-transformers`，用 `all-MiniLM-L6-v2` 模型本地生成向量（约 80MB）
- 方案B：调用讯飞或 DeepSeek 的 Embedding API
- 删除 `SimpleEmbeddingFunction` 类
- 在 `ContentGenAgent`、`MindMapAgent` 等生成资源后自动向量化入库

### 6. 安全过滤接入所有 Agent 的输出

**文件**：`backend/services/safety_service.py`

**当前状态**：`SafetyService.check()` 已实现但**从未被调用**，是死代码。

**做什么**：
- 在 `ChatAgent.stream()` 的每个 chunk 输出前调用安全检查
- 在 `ContentGenAgent`、`MindMapAgent` 等的内容返回前调用安全检查
- 在 `chat_service.py` 的路由层增加统一的安全过滤拦截点
- 防幻觉方面：为内容生成 Agent 的 prompt 增加"引用来"、"标注不确定"等约束

### 7. LLM 调用增加超时、重试和错误兜底

**文件**：`backend/core/llm_client.py`

**当前状态**：调用没有任何保护。

**做什么**：
- `AsyncOpenAI()` 加 `timeout=httpx.Timeout(60.0, connect=10.0)`
- 加 retry 逻辑（tenacity 或简单循环重试 2 次）
- API 超时/失败时返回用户友好的错误提示，而不是 500 Server Error
- 考虑增加降级策略：主 API 挂了可以切备用 LLM

### 8. 修复 ProfileAgent 的 DB session 生命周期

**文件**：`backend/agents/profile_agent.py:80-82`

**问题**：
- `asyncio.create_task` 创建的 fire-and-forget 任务没有错误处理
- DB session 在 `finally` 中关闭，事件消费者可能拿到已关闭的 session
- `import` 语句写在函数内部，不应如此

**做什么**：
- 将事件发送移到 `finally` 之外，在 session 关闭前完成
- 去掉函数内的 import，改为文件顶部导入
- 给 `create_task` 的任务加 try/except 兜底

### 9. 删除 EchoAgent 注册

**文件**：`backend/main.py:60`

`EchoAgent` 在注册表中，意图路由可能将正常用户请求路由到它，返回 `[Echo] 用户消息`。

**做什么**：
- 从 `main.py` 中删除 `register(EchoAgent())` 和相关 import
- 保留 `echo_agent.py` 文件用于开发调试（不再注册到生产路由）

## 🟡 中危（后期演示/答辩时可能暴露的问题）

### 10. SQLite 并发瓶颈

**当前状态**：SQLite + `check_same_thread=False` 允许并发读但写操作串行。多人同时使用或前端轮询频繁时会出现 `database is locked`。

**做什么**：
- 答辩前切换到 PostgreSQL（推荐，赛题对数据库不做限制）
- 或降低前端轮询频率（当前 30 秒一次，改为按需刷新）
- 或给 SQLite 加 `WAL` 模式 + busy timeout

### 11. 用户数据无隔离

**当前状态**：所有 API 通过 query parameter 传 `user_id`，任何用户可以访问任何人的数据。

**做什么**：
- 最小方案：用 `localStorage` 的 `user_id` 做基于 session 的简单隔离
- 正式方案：引入 JWT token 或简单的 API Key 机制
- 至少在前端层面防止 URL 篡改

### 12. 修复 `datetime.utcnow` 废弃警告

**影响文件**：
- `backend/models/student.py:18-19`
- `backend/models/resource.py:15`
- `backend/models/learning_path.py:13`

**做什么**：统一替换为：
```python
from datetime import datetime, timezone
default=lambda: datetime.now(timezone.utc)
```

### 13. Config API 安全加固

**文件**：`backend/api/routes/config.py`

**问题**：前端可以 POST 新密钥覆盖服务器配置。

**做什么**：
- 配置修改接口增加简单的鉴权（如环境变量 ADMIN_TOKEN）
- 或者前端只能读取配置，不能写入（写入通过环境变量或管理后台）
- GET 接口返回的 `api_key` 已经做了 mask 处理（✅），确认 `api_secret` 也被 mask

### 14. 缺乏请求日志和监控

**当前状态**：没有任何请求日志，出问题时无法定位。

**做什么**：
- 加一个简单的中间件：记录每个请求的路径、耗时、user_id
- Agent 调用链记录：哪条消息触发了哪个 Agent，耗时多久
- 至少用 Python `logging` 替代 `print()`
