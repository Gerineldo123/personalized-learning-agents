## 模块间通信规则

```
请求流向:
  用户 → API Routes → Services → Agents → Core (LLM/DB/Vector)

依赖方向 (从底层到高层):
  utils ← core ← agents ← services ← api
              ↑          ↑
           models      schemas
```

**硬约束：**
1. `api/` 只能 import `services/` 和 `schemas/`
2. `services/` 可以 import `agents/`, `core/`, `models/`
3. `agents/` 可以 import `core/`, `models/`，不可相互 import
4. `core/` 只 import `utils/` 和第三方库
5. **禁止环形依赖**：同级模块通过 `events/` 事件系统通信

## 智能体可插拔设计

每个智能体遵循统一接口，通过注册表管理：

```python
# agents/base.py
from abc import ABC, abstractmethod

class BaseAgent(ABC):
    name: str
    description: str

    @abstractmethod
    async def process(self, state: dict) -> dict:
        ...

# agents/registry.py
_registry: dict[str, BaseAgent] = {}

def register(agent: BaseAgent):
    _registry[agent.name] = agent

def get_agent(name: str) -> BaseAgent:
    return _registry[name]

def get_all_agents() -> list[BaseAgent]:
    return list(_registry.values())
```

**添加新功能只需 3 步：**
1. 新建 `agents/new_agent.py`，继承 `BaseAgent`
2. 新建对应 `api/routes/new_feature.py`
3. 在 `main.py` 注册路由和智能体

**删除功能只需 2 步：**
1. 删除 agent 文件夹 + 对应 api route
2. 删除 `main.py` 中注册行

## 关键设计决策说明

| 决策 | 说明 |
|------|------|
| `events/` 事件系统 | 避免 agent 间直接调用。如"评估智能体修改画像"应通过发事件，而非 import profile_agent |
| `schemas/` 独立 | API 契约与 ORM 模型分离，修改数据库不影响前端 |
| `main.py` 只组装 | 入口文件不写逻辑，只 import 并注册路由、中间件、agent |
| 目录即模块 | 每新增功能新增目录/文件，删除也只需删除对应目录/文件 |
| TTS/Live2D 单独目录 | 数字人功能可能不稳定，独立封装便于整体移除 |
