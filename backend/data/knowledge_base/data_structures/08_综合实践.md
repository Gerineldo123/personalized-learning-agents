# 数据结构综合实践：校园导航与学习任务管理

> 本文为项目团队原创实践材料，覆盖数据结构课程全部核心知识点。

## 实践目标

把线性表、栈与队列、树与二叉树、图、查找算法、排序算法和哈希表组合到可运行系统中；能够说明每个结构承担的职责；使用测试数据验证复杂度判断，而不是只完成界面演示。

## 项目一：校园导航系统

系统把建筑物建模为图的顶点，道路建模为边，距离或预计时间作为权。邻接表适合道路相对稀疏的校园网络。建筑信息可放在线性表中，并使用哈希表建立名称到顶点编号的索引。用户输入起点和终点后，系统使用 Dijkstra 计算非负权最短路径，再通过前驱数组还原完整路线。

功能应包括建筑增删、道路维护、单源导航、路线展示和异常输入处理。若道路临时关闭，可在边上维护可用状态；若不同时间道路耗时变化，可把权值改为动态估计，但应说明静态 Dijkstra 对时变网络的局限。

验收时至少准备连通图、非连通图、重名建筑、起终点相同和不存在路径等测试。性能测试应逐步增加顶点和边数量，比较邻接矩阵与邻接表的空间占用和遍历时间。

### Python 代码骨架：邻接表最短路径

```python
from heapq import heappop, heappush


def shortest_paths(graph, start):
    distance = {node: float("inf") for node in graph}
    distance[start] = 0
    queue = [(0, start)]
    while queue:
        current_distance, node = heappop(queue)
        if current_distance != distance[node]:
            continue
        for neighbor, weight in graph[node]:
            candidate = current_distance + weight
            if candidate < distance[neighbor]:
                distance[neighbor] = candidate
                heappush(queue, (candidate, neighbor))
    return distance
```

邻接表只保存真实道路，优先队列每次取出当前距离最小的顶点。若道路权值出现负数，该算法的前提不再成立，系统必须拒绝输入或改用其他算法。

## 项目二：学习任务管理系统

课程、章节和任务之间具有层次关系，可使用树组织目录。当天任务使用线性表保存，待处理任务可按优先级进入堆或优先队列。任务 ID 到记录位置使用哈希表快速定位。撤销最近操作可使用栈保存命令；按截止时间或优先级展示时使用稳定排序，保证相同优先级下原有次序可预测。

若任务之间存在先修依赖，可构建有向图并进行拓扑排序。存在环时系统应明确提示依赖冲突，而不是输出不完整顺序。历史任务按时间归档后，可通过二分查找定位时间范围，但前提是归档序列保持有序。

## 示例：结构替换实验

初版校园导航可能用线性表按建筑名称查找，查询一次为 $O(n)$。加入哈希索引后平均查询接近 $O(1)$，但需要额外空间，并在建筑名称变化时同步更新索引。实验应分别统计构建索引时间、单次查询时间和大量查询总时间，避免只展示理论符号。

## 实践检查与答案框架

**问题 1：** 为什么校园导航的建筑表和道路图需要同时存在？

**答案框架：** 图负责顶点间关系和路径计算，建筑表负责名称、坐标、简介等属性；哈希索引把外部名称映射到内部顶点编号，三者职责不同。

**问题 2：** 如何判断学习任务依赖存在环？

**答案框架：** 运行拓扑排序，若处理顶点数少于任务数，则剩余部分存在有向环；也可用 DFS 颜色标记检测回边。
