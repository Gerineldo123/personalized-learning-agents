# 哈希表：映射、冲突处理与装载因子

> 本文为项目团队原创课程资料，对应知识点“哈希表”。

## 学习目标

理解哈希函数和冲突；掌握链地址法与开放定址法；理解装载因子对性能的影响；能够设计扩容策略并认识哈希表平均 $O(1)$ 的条件和边界。

## 基本思想

哈希表通过哈希函数把键映射到有限的桶下标。理想函数应计算快速、确定，并让实际键尽量均匀分布。由于键空间通常大于桶数量，不同键映射到同一位置的冲突不可避免，正确实现必须定义冲突处理方法。

常见整数映射可使用除留余数法 `index = key % capacity`，字符串通常逐字符组合。工程中还要考虑恶意构造键导致大量冲突的安全风险，有些运行时会为字符串哈希加入随机种子。

## 链地址法

链地址法让每个桶保存一个链表或其他容器，冲突键进入同一桶。插入实现简单，装载因子可以超过 1，但每个节点有额外指针开销，内存局部性较弱。查找时先定位桶，再在桶内比较真实键，不能只比较哈希值。

## 开放定址法

开放定址法把所有记录放在桶数组中，冲突后按探测序列寻找其他位置。线性探测缓存友好，但容易形成主聚集；二次探测和双重哈希可改善聚集。删除时不能简单把桶恢复为空，否则会截断其他键的探测路径，通常需要墓碑标记。

## 装载因子与扩容

装载因子 $\alpha = n/m$，其中 $n$ 为元素数、$m$ 为桶数。装载因子增大时冲突概率上升。达到阈值后应申请更大桶数组，并根据新容量重新计算每个键的位置。不能直接复制旧桶，因为下标依赖容量。

扩容一次成本为 $O(n)$，但若按倍数增长，分摊到多次插入后的均摊成本仍可接近 $O(1)$。若每次只增加很小容量，会频繁重哈希并破坏均摊优势。

### Python 代码案例：链地址法核心操作

```python
class HashTable:
    def __init__(self, capacity=8):
        self.buckets = [[] for _ in range(capacity)]

    def put(self, key, value):
        bucket = self.buckets[hash(key) % len(self.buckets)]
        for index, (stored_key, _) in enumerate(bucket):
            if stored_key == key:
                bucket[index] = (key, value)
                return
        bucket.append((key, value))

    def get(self, key):
        bucket = self.buckets[hash(key) % len(self.buckets)]
        for stored_key, value in bucket:
            if stored_key == key:
                return value
        raise KeyError(key)
```

示例省略了扩容，适合展示冲突处理而不是直接用于生产。完整实现还需统计装载因子，并在扩容后重新散列全部键。

## 例题：缓存设计

最近最少使用缓存需要按键快速找到记录，同时维护最近访问顺序。可以组合哈希表和双链表：哈希表把键映射到链表节点，双链表头表示最近使用、尾表示最久未使用。访问、插入和淘汰在平均情况下都能达到 $O(1)$。

## 常见错误

1. 把哈希值相等当成键相等。
2. 扩容后没有重新哈希。
3. 开放定址删除时直接置空，导致后续键查找失败。
4. 声称哈希表任何情况下都是 $O(1)$，忽略冲突和恶意输入。

## 练习与答案

**练习 1：** 为什么哈希表不适合直接完成范围查询？

**答案：** 哈希映射破坏了键的自然顺序，相邻键通常落在无关桶中。范围查询更适合有序数组、B 树或平衡搜索树。

**练习 2：** 容量变化后为什么必须重新计算位置？

**答案：** 桶下标通常包含对容量取模，容量改变会使映射结果改变。直接复制会让查找按照新规则定位不到旧元素。

## 本章小结

哈希表的高效来自均匀映射、受控装载因子和正确冲突处理。平均常数复杂度不是无条件承诺，工程实现必须考虑扩容、删除、内存和安全边界。
