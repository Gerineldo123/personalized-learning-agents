# 排序算法：比较、稳定性与工程权衡

> 本文为项目团队原创课程资料，对应知识点“排序算法”。

## 学习目标

掌握插入、选择、冒泡、快速、归并和堆排序的基本过程；理解稳定性、原地性、最好/平均/最坏复杂度；能够根据规模、初始有序程度、内存和稳定性要求选择算法。

## 基础排序

直接插入排序将当前元素插入前方已有序区间。最坏复杂度为 $O(n^2)$，但数据接近有序时移动次数较少，并且算法稳定。选择排序每轮选择最小元素放到前端，比较次数稳定为 $O(n^2)$，交换次数较少，通常不稳定。冒泡排序通过相邻逆序交换让较大元素逐步移动到末尾，加入“本轮无交换”标记后可提前结束。

## 分治排序

归并排序将序列递归分成两半，分别排序后合并。时间复杂度稳定为 $O(n\log n)$，容易保持稳定，但数组实现通常需要 $O(n)$ 辅助空间。它适合外部排序，因为可以按顺序读取多个已排序数据段。

快速排序选择枢轴，将小于枢轴和大于枢轴的元素分到两侧，再递归处理。平均复杂度为 $O(n\log n)$，缓存局部性好，工程中非常常用。若每次枢轴都极端不平衡，最坏退化为 $O(n^2)$，递归深度也会达到 $O(n)$。随机选择、三数取中和三向切分可以改善常见退化场景。

### Python 代码案例：三向快速排序

```python
def quick_sort_three_way(values):
    if len(values) <= 1:
        return values[:]
    pivot = values[len(values) // 2]
    less = [value for value in values if value < pivot]
    equal = [value for value in values if value == pivot]
    greater = [value for value in values if value > pivot]
    return quick_sort_three_way(less) + equal + quick_sort_three_way(greater)
```

该实现用三个线性表清晰展示三向切分，便于理解重复元素的处理。它不是原地排序，递归层还会创建新列表，因此工程实现需要进一步控制额外空间。

## 堆排序

堆排序先建立最大堆，再反复交换堆顶和末尾元素，并缩小堆范围后向下调整。建堆可在 $O(n)$ 完成，整体最坏复杂度为 $O(n\log n)$，额外空间较小，但通常不稳定，实际缓存表现也可能弱于快速排序。

## 稳定性

若两个关键字相等的记录排序后相对次序不变，则算法稳定。稳定性在多关键字排序中很重要：先按次要关键字稳定排序，再按主要关键字稳定排序，可以保留次要次序。稳定与否是算法性质和具体实现共同决定的，不能只看名称。

## 例题：选择算法

少量且接近有序的数据可考虑插入排序；需要稳定且数据可全部放入内存时可使用归并排序；一般内存数组追求平均速度可使用经过优化的快速排序；需要严格最坏界限且空间受限时可考虑堆排序。标准库通常采用混合策略，而不是单一算法。

## 常见错误

1. 把快速排序平均复杂度当成最坏复杂度。
2. 比较稳定性时没有定义相等元素携带的附加信息。
3. 归并时相等元素优先取右侧，意外破坏稳定性。
4. 快速排序分区指针不前进，遇到重复值时死循环。

## 练习与答案

**练习 1：** 为什么归并排序适合链表？

**答案：** 链表可以通过修改指针完成分割和合并，不需要数组式随机访问，也可以避免大块辅助数组复制。

**练习 2：** 数据包含大量重复键时，快速排序如何改进？

**答案：** 使用三向切分，把元素划分为小于、等于和大于枢轴三部分，等于部分无需继续递归。

## 本章小结

排序没有脱离场景的绝对最优。选择时应同时说明数据规模、分布、稳定性、空间、最坏界限和底层存储方式。
