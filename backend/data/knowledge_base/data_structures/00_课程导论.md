# 数据结构课程导论与复杂度分析

> 本文为项目团队原创课程资料，适用于计算机类本科生的数据结构入门与复习。

## 学习目标

完成本章后，学生应能解释数据、数据元素、逻辑结构、存储结构和抽象数据类型之间的关系；能够用渐进复杂度描述算法规模增长趋势；能够根据访问、插入、删除、查找和排序等操作需求选择合适的数据结构。

## 从问题到数据结构

数据结构研究的不是“把数据放进变量”这么简单，而是研究数据元素之间的关系，以及这种关系怎样映射到计算机存储。课程中的线性表、栈、队列、树、图和哈希表分别适合表达不同关系。通讯录天然接近线性结构，文件目录适合树结构，城市道路适合图结构，账号到用户记录的快速映射适合哈希表。

一个完整的数据结构设计通常包含三个层次：逻辑结构说明元素之间是什么关系；存储结构说明关系怎样落到内存；操作集合说明系统允许执行哪些动作。抽象数据类型只规定“能做什么”，不强制“怎样实现”。例如栈要求后进先出，但可以使用顺序数组，也可以使用链表实现。

## 算法与复杂度

算法应具有确定性、有限性、可执行性，并对合法输入产生预期输出。评价算法不能只看某一次运行耗时，因为硬件、编译器和输入分布都会影响结果。渐进复杂度关注输入规模增大时基本操作次数的增长速度。

若循环执行次数为常数，时间复杂度通常为 $O(1)$；单层遍历为 $O(n)$；两层独立遍历通常为 $O(n^2)$；每次把问题规模减半的过程常见于 $O(\log n)$；分治排序通常达到 $O(n\log n)$。复杂度分析应先确定输入规模，再确定重复最频繁的基本操作，最后保留增长最快的项并忽略常数系数。

空间复杂度衡量算法除输入数据外额外占用的空间。递归调用会使用调用栈，原地算法并不意味着完全不使用辅助变量，而是辅助空间不随输入规模显著增长。

### Python 代码案例：用计数实验观察增长趋势

```python
def pair_comparisons(values):
    comparisons = 0
    for left in range(len(values)):
        for right in range(left + 1, len(values)):
            comparisons += 1
    return comparisons
```

当输入规模从 $n$ 增长到 $2n$ 时，比较次数约增长到原来的四倍，这与两层相关循环的 $O(n^2)$ 趋势一致。实验只能帮助验证趋势，复杂度结论仍应来自对基本操作次数的推导。

## 例题：选择存储结构

某系统维护十万条学生记录，需求包括按学号高频查询、偶尔按成绩排序、极少删除。若仅使用链表，按学号查询需要逐项扫描；若使用哈希表维护学号索引，平均查询可接近 $O(1)$。成绩排序可以临时提取记录引用形成数组，再使用稳定排序。这个例子说明真实系统往往组合多种结构，而不是追求一种“万能结构”。

## 常见错误

1. 把最坏复杂度当成每次运行的实际耗时。
2. 只比较时间复杂度，不考虑内存、稳定性和数据规模。
3. 看见“查找”就选择二分查找，忽略数据必须有序且支持随机访问。
4. 把抽象数据类型和某一种具体实现混为一谈。

## 练习与答案

**练习 1：** 一个循环每次令 `n = n // 2`，直到 `n` 为零，循环次数是什么量级？

**答案：** 每次规模减半，执行次数约为 $\lfloor\log_2 n\rfloor+1$，时间复杂度为 $O(\log n)$。

**练习 2：** 为什么“数组插入一定比链表慢”不严谨？

**答案：** 链表只有在已经取得插入位置节点时才能以 $O(1)$ 调整指针；若需要先按序号定位，仍需 $O(n)$。数组尾部且容量足够时插入可为均摊 $O(1)$。

## 本章小结

数据结构选择必须同时考虑数据关系、操作频率、规模、内存布局和实现复杂度。后续章节将分别研究不同结构的性质，但所有结论都应回到“约束条件下的工程权衡”。
