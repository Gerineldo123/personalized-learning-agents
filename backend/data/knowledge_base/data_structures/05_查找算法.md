# 查找算法：有序查找、树表查找与性能边界

> 本文为项目团队原创课程资料，对应知识点“查找算法”。

## 学习目标

掌握顺序查找和二分查找；理解静态查找与动态查找的差异；能够使用循环不变量解释二分查找边界；理解二叉搜索树性能取决于树高。

## 顺序查找

顺序查找从一端开始逐项比较，适用于数据量较小、无序或只查找一次的场景。最坏需要比较 $n$ 次，时间复杂度为 $O(n)$。它的优势是前提少，可以在数组、链表和流式数据上工作。

## 二分查找

二分查找要求数据按目标键有序，并且能够高效访问中间位置。每次比较后排除约一半范围，时间复杂度为 $O(\log n)$。在链表上虽然逻辑有序，但访问中点需要线性移动，因此通常不能获得数组上的优势。

实现二分查找最重要的是区间定义。若使用闭区间 `[left, right]`，循环条件是 `left <= right`，排除中点后更新为 `left = mid + 1` 或 `right = mid - 1`。若使用左闭右开区间 `[left, right)`，循环条件和更新规则应采用另一套一致约定。混合两套规则容易死循环或漏掉边界元素。

```python
def binary_search(values, target):
    left, right = 0, len(values) - 1
    while left <= right:
        middle = left + (right - left) // 2
        if values[middle] == target:
            return middle
        if values[middle] < target:
            left = middle + 1
        else:
            right = middle - 1
    return -1
```

## 查找变体

很多题目不是寻找“任意一个等于目标的元素”，而是寻找第一个不小于目标的位置、最后一个不大于目标的位置或重复元素的左右边界。解决方法仍是二分，但命中时不能立即返回，而应记录候选并继续收缩区间。明确谓词在区间上如何从假变真，是设计边界二分的关键。

## 动态查找

当集合频繁插入和删除时，维护有序数组会产生移动成本。二叉搜索树能够在结构较平衡时提供近似 $O(\log n)$ 的查找和更新；哈希表适合精确键查询；若需要范围查询和有序遍历，则平衡搜索树更合适。

## 常见错误

1. 数据未排序就使用二分查找。
2. `left`、`right` 的边界定义前后不一致。
3. 计算中点时在固定宽度整数语言中发生溢出。
4. 需求是找左边界，却在首次命中时直接返回。

## 练习与答案

**练习 1：** 长度为 1024 的有序数组，二分查找失败时比较次数是什么量级？

**答案：** $O(\log_2 1024)=O(10)$，具体次数与实现边界和目标位置有关。

**练习 2：** 为什么频繁插入的数据不一定适合维护有序数组？

**答案：** 查找虽可二分，但插入时需要找到位置并移动大量元素，最坏为 $O(n)$。应根据查询和更新比例综合选择结构。

## 本章小结

查找算法的选择依赖数据是否有序、是否支持随机访问、是否频繁更新以及是否需要范围查询。二分查找的正确性来自稳定的区间不变量，而不是记忆某一段代码。
