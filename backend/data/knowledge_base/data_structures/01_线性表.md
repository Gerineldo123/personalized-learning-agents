# 线性表：顺序存储、链式存储与工程选择

> 本文为项目团队原创课程资料，对应知识点“线性表”。

## 学习目标

理解线性表的一对一逻辑关系；掌握顺序表、单链表、双链表的核心操作；能够分析插入、删除、访问和查找的复杂度，并根据业务场景选择实现。

## 基本概念

线性表是由有限个同类型数据元素构成的有序序列。除第一个元素外，每个元素有且仅有一个直接前驱；除最后一个元素外，每个元素有且仅有一个直接后继。这里的“有序”强调位置次序，并不表示数值已经排序。

顺序表使用连续存储空间，通过首地址和元素下标计算任意位置，因此随机访问为 $O(1)$。在中间插入或删除元素需要移动后续元素，最坏为 $O(n)$。动态数组通常预留容量，容量不足时申请更大空间并复制元素，因此尾部追加的单次最坏代价是 $O(n)$，但长期均摊代价可视为 $O(1)$。

链表使用节点保存数据域和链接域，节点在内存中不必连续。已知节点后插入或删除只需调整有限个指针，但按序号访问必须从头移动，复杂度为 $O(n)$。双链表增加前驱指针，便于反向遍历和删除当前节点，但占用更多空间并增加指针维护成本。

## 单链表关键操作

在节点 `prev` 后插入 `node` 时，应先令 `node.next = prev.next`，再令 `prev.next = node`。顺序不能颠倒，否则可能丢失原有后继链。删除 `prev` 的后继节点时，应保存待删除节点，再令 `prev.next = target.next`。工程实现还要处理空表、头节点、尾节点和非法位置。

带头节点的链表使用一个不保存业务数据的哨兵节点，可以统一首元素插入和普通位置插入的代码。哨兵并不改变逻辑元素个数，却能减少边界分支，是常见的工程技巧。

## Python 示例

```python
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node

def insert_after(previous, value):
    new_node = Node(value, previous.next)
    previous.next = new_node
    return new_node
```

## 例题与分析

若系统频繁按下标读取元素、数据规模稳定且很少在中间插入，应优先考虑顺序表。若系统已经持有节点引用并频繁进行局部插入删除，链表更合适。若既要按键快速定位又要维护顺序，可以组合哈希表和双链表，哈希表负责定位，双链表负责次序维护。

## 常见错误

1. 修改指针顺序错误导致后续链表丢失。
2. 删除尾节点后没有同步维护尾指针。
3. 将链表的“插入 $O(1)$”误解为“找到插入位置也是 $O(1)$”。
4. 遍历时删除当前节点，却继续使用已经失效的引用。

## 练习与答案

**练习 1：** 长度为 $n$ 的顺序表在第一个位置插入元素，需要移动多少个元素？

**答案：** 原有 $n$ 个元素都要后移，移动次数为 $n$，时间复杂度为 $O(n)$。

**练习 2：** 设计删除单链表倒数第 $k$ 个节点的方法。

**答案：** 使用快慢指针。快指针先前进 $k$ 步，再让快慢指针同步前进；快指针到达末尾时，慢指针位于目标节点之前。使用哨兵节点可统一删除首节点的情况。

## 本章小结

顺序表以连续空间换取快速随机访问，链表以链接开销换取灵活的局部修改。判断优劣必须说明是否已知位置、操作分布、缓存友好性和内存约束。
